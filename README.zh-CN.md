# dsh-soul

[[English](./README.md) | 简体中文]

**dsh-soul 给 DeepSeek Harness 加一个「灵魂」。**

开箱的宿主是个能干的多面手，但它的身份是部署写死的：一次安装一个设定，在写 composition 的那一刻就定下来了。这个插件把身份变成你自己掌握的数据——用 Markdown 写的人设卡存在设置里，按会话和工作区解析出这一轮该用哪张，作为系统提示词里的**一个** section 注入，每轮重新解析。模型能读自己的人设，改不了它。

一个独立插件：只读写 `soul` 这一个设置文档，不碰别的插件的命名空间，不落磁盘文件，也没有共享状态。

## 为什么要一个「灵魂」

- **一次安装，几个自己。** 同一套 harness，在这个工作区该是干脆的评审员，在那个工作区该是耐心的老师。一张卡把这件事变成设置，而不是 fork、预设，或者装第二份。
- **灵魂是文本，所以看得见。** 助手对自己的一切认知都是可读、可 diff、可进版本库的 Markdown，而不是烧进应用里的不透明系统串。
- **它能活过这一轮。** 卡片在拼装提示词时重新读，而不是在开会话那一刻快照下来——改完卡片，下一轮就生效，不用重启，也不用重开会话。
- **它始终是你的。** 人设文字能进提示词，只因为你亲手打了它。没有任何工具、路由或钩子允许模型去写一张卡。

> [!IMPORTANT]
> **设计取舍（按约束代码的先后顺序）**
>
> 1. **存设置，不存文件。** 卡片就是 `soul` 命名空间里的普通设置值：跟随宿主的设置热更新、在设置 UI 里可见、沿用宿主的 revision 校验。不落数据目录，也不自创文件格式。
> 2. **一个 section，一个主人。** 提示词 section 叫 `dsh-soul:persona`——按包名收窄，而不是按功能起名。宿主遇到同名 section 会在 `apply()` 里直接抛错，所以 `soul:persona` 这种通用名字恰恰是最容易撞车、把整个插件带崩的那一个。
> 3. **每次只写最小的那一个键。** 会话选择只写 `sessions.<id>`，工作区选择只写 `workspaces.<path>`。整表写入会把下层配置复制进用户层，把用户没做过的选择钉死。
> 4. **宿主点头才算存上。** 写完之后拿新快照核对一遍；`mutate` 返回成功但值没变（非 volatile 路径、revision 冲突）会被当成失败报出来，草稿留在表单里。
> 5. **对模型只读。** `persona_read` 只是让 agent 能引用自己的人设；没有写入工具、没有接受卡片正文的路由，除了用户自己写进卡片的文字之外没有别的注入面。

## 你能拿到什么

| 界面 | 位置 | 作用 |
| --- | --- | --- |
| **设置卡** | 设置 → 插件 → `dsh-soul` → 包含的组件 → `dsh-soul ›` | 卡片列表、编辑器（新建 / 重命名 / 改正文 / 删除 / 设为默认）、按工作区的选择、两个开关 |
| **会话切换器** | 聊天标题栏，每个会话一个 | 给「这个会话」指定卡片，或者把这个会话的人设关掉 |
| **新会话切换器** | 新会话页的选项区 | 发第一条消息之前就能选；保存期间占住输入框 |
| **`persona_read`** | agent 的工具列表 | 返回调用方会话生效的卡片（名字、正文，以及是哪一层选中的） |
| **提示词 section** | 系统提示词 `dsh-soul:persona` | 生效卡片的正文，每一轮重新解析 |

## 卡片是怎么选出来的

解析按 agent、在拼装提示词时进行，顺序如下：

| # | 层 | 键 | 说明 |
| --- | --- | --- | --- |
| 1 | 会话 | `sessions.<sessionId>` | `"none"` 表示关掉人设，**并终止查找**——说了关的会话不会掉到工作区卡片上去 |
| 2 | 工作区 | `workspaces.<path>` | 先按原样匹配，再按规范化路径做大小写不敏感匹配（同一个 Windows 目录在不同会话里大小写会不一样） |
| 3 | 默认 | `active` | 标了 默认 的那张卡 |
| — | — | — | 都没有：section 渲染成空字符串，宿主不会把它写进提示词 |

存下来的选择如果指向一张已经不存在的卡（或正文为空白的卡），按「没有选择」处理并继续往下找，而不是悄悄把默认卡压掉。设置卡里这种工作区行会保留显示并打上标记，方便清掉。

`skipSubagents`（默认开）让被委派的子会话不注入人设：子会话本来就继承父会话的提示词，再重复一遍既费 token 又糊掉边界。解析本身不受它影响——`persona_read` 和切换器看到的仍然是「这个会话本会注入什么」。

## 环境要求

- dsh `>=0.2.0-rc.2 <0.3.0-0`，其中 `0.2.1-rc.*` 各版本在 `dsh.compatibility` 里逐个列出
- Node `>=20.18`
- React 18 作为 peer（由宿主提供）
- 支持 `web` 与 `desktop` 两个 profile

## 安装

从源码安装——`link:` 只建一个指向目录的软链，宿主直接从这个源码目录 import：

```sh
cd <checkout>
npm ci                                          # 开发依赖只给测试用，运行时不需要
dsh plugin --profile desktop add link:<源码目录的绝对路径>
```

web profile 把 `--profile` 换成 `web`。重启 DSH，然后打开 **设置 → 插件 → dsh-soul**；卡片在组件行里，点 包含的组件 中的 `dsh-soul ›` 进去。

包发布到 registry 之后，同一条命令去掉 `link:` 就是按名字安装：

```sh
dsh plugin --profile desktop add dsh-soul
```

bundle patch（`cordis.patch.yml`）声明的加载器条目是 `id: dsh-soul`——和包名、设置命名空间是同一个字符串：插件页会把行 id 和模块名并排印出来，两个不同的名字在那儿看着就像两个插件。这个 id **就是**设置命名空间：改名等于把所有已存的卡片弄丢。0.2 之前这一行叫 `soul`，卡片仍会回退读取那个命名空间，所以还没改名的 profile 也能用。

## 快速上手

1. 打开卡片（插件 → `dsh-soul` → `dsh-soul ›`），填名字和正文 Markdown，保存。
2. 标成 默认，或者分配给某个工作区；聊天标题栏可以按会话现切。
3. 随便问一句。变的是系统提示词，不是工具——下一轮起卡片就生效。
4. 想让某个会话不挂人设，在它的标题栏里选 关闭；工作区和默认层只为这一个会话跳过。

## 设置项

| 键 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `cards` | `{ [名字]: markdown }` | `{}` | 卡片本体。空名字、空正文会被拒绝；`__proto__` 与 `prototype` 不能当名字 |
| `active` | `string` | `""` | 默认卡的名字 |
| `sessions` | `{ [sessionId]: 卡名 \| "none" }` | `{}` | 按会话的选择 |
| `workspaces` | `{ [路径]: 卡名 \| "none" }` | `{}` | 按工作区的选择 |
| `showPersonaSwitcher` | `boolean` | `true` | 是否在聊天标题栏和新会话页显示切换器 |
| `skipSubagents` | `boolean` | `true` | 是否跳过子会话的人设注入 |

全部是 volatile 的，设置页改了立刻生效，不用重启。

## 怎么写一张卡

卡是提示词，好用的都很短。值得写进去的：

- **它是谁**：名字、角色、说话的调门。
- **它怎么称呼你**：称呼、语言、是解释还是断言。
- **它拒绝什么**：哪种免责声明、哪种含糊、哪种习惯会把这层身份破坏掉。
- **它为了什么**：这个身份服务的那件事，一句话。

不值得写的：工具使用规则、安全策略，以及任何其实是「这一次任务」的指令。那些属于需要它们的那一轮；人设是常量，不是任务。

## 内部细节

设置卡注册在 `plugins.row.config` 上，键是 `dsh-soul#dsh-soul`（`<包名>#<行 id>`），同时保留旧的 `dsh-soul#soul`——插件管理器就是拿这个键判断「这一行能不能点开配置页」，所以插件页只列出这一行，正文都在行页面里；同一个注册还回答 summary 视图，给行描述一句摘要（卡片数量与默认卡）。卡片本体是手写的 ModuleLoader bundle，样式只取自宿主主题变量（`--dsw-alias-*`、`--dsw-radius-*`、`--dsw-focus-ring-*`），类名统一 `__sl_` 前缀，两个插件不会互相改样式；所有控件立刻写入、一个动作一批操作，不做整页保存栏。

卡片背后是一个同源 `POST` 路由：`POST /api/soul/workspaces` 列出宿主的工作区，让映射能按标题显示。`/api` 下的精确路由不过宿主的围栏，所以它自己做检查——非 JSON 请求 `415`，跨站 `Origin`（包括 `Origin: null`、`Sec-Fetch-Site: cross-site`）`403`。判定同源是拿 `Origin` 的 host 与请求的 `Host` 头比较，**不是**与 `request.url` 比较：宿主在把请求交给路由之前会把 URL 重写到 `http://dsh.internal` 这个合成基址上，拿 URL 比会把每一次真实调用都拒掉。完全没有 `Origin` 头的请求放行——那是本地脚本，不是浏览器。返回体带 `{version: 1, …}`，版本对不上按「不可用」处理，不去猜。

## 开发

```bash
npm install --cache ./.npm-cache    # 本地缓存，避免沙箱去写 %LOCALAPPDATA%
npm test
```

`npm test` 在同一个进程里跑 **114 个测试**（`--experimental-test-isolation=none`：受限沙箱里测试运行器 fork 子进程会失败）：

- `persona.test.mjs` —— 解析顺序、`none` 哨兵值、过期与空白选择、路径规范化、子会话门
- `routes.test.mjs` —— 请求守卫（415 / 403 / 同源）、构建失败、版本信封
- `host-plugin.test.mjs` —— 用一个假宿主验证插件面：section 注册、工具 schema、工作区路由、重名行为
- `host-contract.test.mjs` —— 同样这些断言打真实的 `@deepseek-ai/cordis` + `dsh-system-prompt` + `dsh-tools`，包括 disposer 真的会注销
- `client-bundle.test.mjs` —— bundle 卫生：loader id、require、注入的服务、slot 元信息、命名空间回退、中英词条对齐、没有死词条
- `client-settings.test.mjs` —— 用真组件驱动卡片：新建、重命名（同一批）、两次点击删除、单键写入、被拒绝、只读，以及组件行的摘要
- `client-switcher.test.mjs` —— 会话切换器：三种状态、单键写入、隐藏、占住输入框

客户端测试把出货的 `client.js` 载入一个小型 hooks 运行时，而不是复制一份代码，所以断言打的就是真正发布出去的那个文件。
